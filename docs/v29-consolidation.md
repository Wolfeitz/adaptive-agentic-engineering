# v0.29 consolidation: non-destructive integration contract

This branch preserves the existing executable Python AAE core. The v0.28 modular package is an input for reconciliation, not permission to replace the functioning repository with Markdown.

## Keep from the existing implementation
- Semantic compiler and provenance-bearing task packets; explicit conflict/clarification and source authority.
- Skill registry, discovery, digest checks, safety decisions and invocation telemetry.
- Event routing and deterministic control checks, idempotency, evidence authority and outcome reconciliation.
- Native adapter contracts, work-tracker integrations, CI and tests.

## Integrate from v0.28
- Full adaptive discovery, requirements and ticket hygiene, environment and architecture assessment.
- Proactive *external* research into stack-specific skills, specialists, hooks, MCP and useful tools.
- Existing HVE, team, user and organization capability inventory and reconciliation before creating duplicates.
- Just-in-time multi-repository work-start, respecting discovered Git naming and project worktree policy.
- Approval and durable obligations for cloud spend, privileged actions, cleanup and agent/model economics.
- Native runtime wiring and fresh-session invocation proof for new components, with exact paths and verification manifests.
- Original-task outcome acceptance: **no silent downgrade from full bootstrap to a limited pilot**.
- Proportionate safeguards for homelab and enterprise, with approved project authority not self-invented rules.
- No unapproved overwrites of HVE or managed assets; no contradictory active older AAE instructions.

## Conformance status
This branch adds an executable completeness assessor and negative tests; it is **not** a finished v29 integration. The existing engine and tests are intentionally not replaced. Do not claim fresh IDE hook interception or complete v28 capability migration without proof.

Use `aae.bootstrap_acceptance.assess(record)` to distinguish incomplete bootstrap outcomes from fully evidenced ones. This check reports evidence; it is not a sandbox, authentication control, or substitute for native IDE integration.

## Completion and scoped exclusions

`original_scope_reconciliation` is mandatory and cannot be `not_applicable` in
either validator. It must be evidenced and verified before reporting `COMPLETE`.
Individual checklist implementations remain conditional on reasoned assessment;
legitimate scoped exclusions do not require installing new artifacts. See the
[decision ledger completion contract](v29-decision-ledger.md#completion-and-scoped-exclusions).
