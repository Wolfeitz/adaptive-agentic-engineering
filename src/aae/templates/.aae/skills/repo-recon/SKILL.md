# Repository Reconnaissance

## Outcome

Produce the smallest evidence packet that establishes repository authority, relevant architecture and precedent, environment constraints, ownership boundaries, and current version-control or runtime state for the requested decision.

## Procedure

1. State the decision this reconnaissance must support and the evidence categories it requires.
2. Read applicable repository instructions and authoritative intent before broad exploration.
3. Locate relevant entrypoints, dependency boundaries, configuration precedence, representative implementations, tests, and ownership records with targeted search.
4. When runtime state matters, distinguish checkout evidence from live process, container, listener, data, and provider evidence.
5. Record confirmed facts, repository-backed inferences, hypotheses, and unknowns separately with source paths or commands.
6. Stop when the next decision is supported; do not preload unrelated repository history.

## Completion contract

The result cites its sources, identifies applicable authority and boundaries, distinguishes observed state from inference, lists material evidence gaps, and is bounded to the current decision.
