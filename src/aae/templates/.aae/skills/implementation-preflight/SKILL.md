# Implementation Preflight

## Outcome

Establish a bounded, evidence-backed implementation approach before modifying the repository or runtime.

## Procedure

1. Confirm the authorized outcome, acceptance criteria, non-goals, authority sources, and required approvals.
2. Trace the live or imported implementation path before declaring code dead or selecting a replacement.
3. Find representative patterns and boundaries already owned by the repository.
4. Map affected interfaces, data, callers, tests, operations, and rollback paths.
5. Evaluate dependencies and shared services against project requirements rather than availability alone.
6. Define verification proportional to risk, including runtime or resource-lifecycle evidence where needed.
7. State assumptions and stop conditions that would materially change the approach.

## Completion contract

The approach is traceable to authority and precedent, impact and rollback are explicit, verification can demonstrate the outcome, and material unknowns are resolved or marked as stop conditions.
